# Changedoc: Wire `_fetch_*_for_display` to `api.get_*_detail()`

**Date:** 2026-07-01
**Reason:** Step 3 of the fetch-and-swap plan. `projects.py`/`contacts.py`/
`organizations.py`'s `_fetch_*_for_display` functions currently query
`projects.projects`/`identity.contacts`/`identity.organizations` directly
— the exact inconsistency `07_detail_views.sql`/`07_detail_api.sql` were
built to close. This changedoc is the Python side of that: the three
functions now call the `api.get_*_detail()` functions confirmed working
in pgAdmin.

**project_rules.md reviewed — no exceptions.** Single canonical
implementation (the view defines the shape once; Python no longer
duplicates it in a hand-written JOIN), tests included for the new
behavior.

**One real response-shape change, flagged rather than silent:**
`_fetch_project_for_display()`'s old direct query joined in `type`/
`status` *name* strings alongside `type_id`/`status_id`. `v_project_detail`
is a deliberate whitelist of editable fields only (see
`sql_conventions.md`) and doesn't include those joined names, and neither
`get_project()`'s JSON response nor `detail-panel.js`'s `populateForm()`
ever reads `record.type`/`record.status` — only the `_id` variants, plus
`name`/`description`. Confirmed by re-reading `populateForm()`: it maps
`name`, `type_id`, `status_id`, `description`, `title` and nothing else.
Also drops `slug` from the response — `slug` is server-generated by
`api.save_project()` and was never meant to be directly editable, and
nothing reads it either. Contacts and organizations are unaffected: their
old direct queries already returned exactly `id`/`name`/`title`/`notes`
and `id`/`name`/`notes` respectively, matching `v_contact_detail`/
`v_organization_detail` exactly.

**"Not found" changes representation, not behavior.** Before: a missing
record made `db.fetch_one()` return `None` directly. After: `fetch_one()`
always returns one row (it's a function call), whose single column is
`NULL` — so the *value* is still `None` once unwrapped, but the raw
`fetch_one()` return shape a test would need to mock is different
(`{"get_project_detail": None}` instead of bare `None`). The routes'
`if not record: raise HTTPException(404, ...)` checks don't change at
all — this is purely about what test mocks need to simulate.

## 1. `src/curator/web/deps.py`

**Why:** Both `call_proc()` (unwraps a `{success, data, message}`
envelope) and the new detail-fetch functions (unwrap a plain
record-or-`None`) need the identical mechanical step — pull the single
column value out of `fetch_one()`'s result, parse it if it came back as a
JSON string rather than an already-decoded dict. Factored into
`_fetch_json_scalar()`, with `call_proc()` now a thin wrapper over it,
rather than duplicating those three lines in four different places.

### BEFORE (the helper section — rest of the file unchanged)

```python
# ---------------------------------------------------------------------------
# Stored-procedure envelope helper
# Moved here from crew.py (2026-07-01 changedoc) — shared by every route
# module that calls an api.* proc. Not entity-specific, so it belongs in
# shared infrastructure rather than any one route file. Renamed from
# _call_proc to call_proc on the move: the leading underscore signaled
# "module-private," which stopped being true the moment a second module
# needed to import it.
# ---------------------------------------------------------------------------

async def call_proc(db: AsyncDBConnection, sql: str, params: tuple) -> dict:
    """Call a stored proc that returns a single JSONB envelope and unwrap it.

    Every api.* proc returns {"success": bool, "data": ..., "message": str}.
    fetch_one() gives back a dict keyed by the proc's column name (e.g.
    {"save_project": {...}}); this pulls out that single value and parses
    it if dbkit returned it as a JSON string rather than an already-decoded
    dict (encoding-dependent — see dbkit client_encoding note in handoff).

    Returns the envelope dict: {"success": ..., "data": ..., "message": ...}
    """
    result = await db.fetch_one(sql, params)
    envelope = list(result.values())[0]
    if isinstance(envelope, str):
        envelope = json.loads(envelope)
    return envelope
```

### AFTER

```python
# ---------------------------------------------------------------------------
# Stored-procedure / detail-fetch envelope helpers
# Moved here from crew.py (2026-07-01 changedoc) — shared by every route
# module that calls an api.* function. Not entity-specific, so it belongs
# in shared infrastructure rather than any one route file.
# ---------------------------------------------------------------------------

async def _fetch_json_scalar(db: AsyncDBConnection, sql: str, params: tuple):
    """Call a function/proc returning a single JSON(B) column and unwrap it.

    fetch_one() gives back a dict keyed by the function's column name
    (e.g. {"get_project_detail": {...}} or {"save_project": {...}});
    this pulls out that single value and parses it if dbkit returned it
    as a JSON string rather than an already-decoded dict
    (encoding-dependent — see dbkit client_encoding note in handoff).

    Returns whatever that single value is: a dict (proc envelope or
    detail record), or None if the column itself is NULL — e.g.
    api.get_project_detail() finding no matching row. Callers that
    always expect a value (call_proc, below) never see None in practice;
    callers that might get a miss (the detail-fetch functions in
    projects.py/contacts.py/organizations.py) check for it themselves.
    """
    result = await db.fetch_one(sql, params)
    value = list(result.values())[0]
    if isinstance(value, str):
        value = json.loads(value)
    return value


async def call_proc(db: AsyncDBConnection, sql: str, params: tuple) -> dict:
    """Call a stored proc that returns a single JSONB envelope and unwrap it.

    Every api.* proc returns {"success": bool, "data": ..., "message": str}.
    Thin wrapper over _fetch_json_scalar — kept as its own name since
    "call a proc and get its envelope" reads more clearly at call sites
    than the more general _fetch_json_scalar would, even though the
    underlying mechanics are identical.

    Returns the envelope dict: {"success": ..., "data": ..., "message": ...}
    """
    return await _fetch_json_scalar(db, sql, params)
```

**Renamed rationale note applies as before** — `_fetch_json_scalar` stays
underscore-prefixed for now since, unlike `call_proc`, it's an
implementation detail import (three route modules import it, but it's
not itself the "public" operation being called — `call_proc` and the
`_fetch_*_for_display` functions are).

## 2. `src/curator/web/routes/projects.py`

**Why:** Replaces the direct JOIN with a call to `api.get_project_detail()`.

### BEFORE

```python
from dbkit.connection import AsyncDBConnection
from curator.web.deps import get_db, call_proc

router = APIRouter()


async def _fetch_project_for_display(db: AsyncDBConnection, project_id: int) -> dict:
    """Fetch a project with joined type and status names for display.

    Returns dict with id, name, slug, description, type, status,
    type_id, status_id keys.
    """
    sql = """
        SELECT
            p.id,
            p.name::text,
            p.slug::text,
            p.description::text,
            p.type_id,
            p.status_id,
            ps.name::text  AS status,
            pt.name::text  AS type
        FROM projects.projects p
        LEFT JOIN projects.project_status ps ON ps.id = p.status_id
        LEFT JOIN projects.project_type   pt ON pt.id = p.type_id
        WHERE p.id = %s
    """
    return await db.fetch_one(sql, (project_id,))
```

### AFTER

```python
from dbkit.connection import AsyncDBConnection
from curator.web.deps import get_db, call_proc, _fetch_json_scalar

router = APIRouter()


async def _fetch_project_for_display(db: AsyncDBConnection, project_id: int) -> dict:
    """Fetch a project via api.get_project_detail() for the detail panel.

    Returns dict with id, name, description, type_id, status_id keys —
    the columns in projects.v_project_detail — or None if not found.

    No longer returns joined type/status *name* strings (the old direct
    query's `type`/`status` columns) or `slug`: v_project_detail is a
    whitelist of editable fields only. Nothing downstream reads those —
    detail-panel.js's populateForm() only maps name/type_id/status_id/
    description/title.
    """
    return await _fetch_json_scalar(
        db, "SELECT api.get_project_detail(%s)", (project_id,)
    )
```

## 5. Tests

Five existing tests need their `fetch_one` mock shape updated — not their
assertions, just what they simulate `fetch_one()` returning, per the
"not found changes representation, not behavior" note above. One new test
class added to `test_deps.py` for `_fetch_json_scalar`'s None-handling,
since that's genuinely new behavior `call_proc` never exercised.

### 5a. `tests/unit/test_deps.py` — add `TestFetchJsonScalar`

**Why:** `_fetch_json_scalar` returning `None` cleanly (rather than
crashing on `None.values()` or similar) is new, load-bearing behavior —
every detail-fetch function depends on it for the "not found" path. Add
after the existing `TestCallProc` class.

```python
class TestFetchJsonScalar:
    """_fetch_json_scalar must handle a NULL column value (the
    api.get_*_detail() "not found" case) by returning None cleanly,
    not by crashing — this is new behavior TestCallProc never exercised,
    since every api.*() proc call_proc wraps always returns a non-null
    envelope.
    """

    @pytest.mark.asyncio
    async def test_returns_none_for_null_column(self):
        """Simulates api.get_project_detail(999999) — fetch_one() returns
        a row whose single column is None, and _fetch_json_scalar should
        pass that through as plain None, not attempt to unwrap or parse
        it further."""
        db = SimpleNamespace(
            fetch_one=AsyncMock(return_value={"get_project_detail": None})
        )

        result = await deps._fetch_json_scalar(
            db, "SELECT api.get_project_detail(%s)", (999999,)
        )

        assert result is None

    @pytest.mark.asyncio
    async def test_returns_dict_for_populated_column(self):
        """Simulates api.get_project_detail(23) finding a real row."""
        record = {"id": 23, "name": "Real Project", "description": None,
                  "type_id": None, "status_id": None}
        db = SimpleNamespace(
            fetch_one=AsyncMock(return_value={"get_project_detail": record})
        )

        result = await deps._fetch_json_scalar(
            db, "SELECT api.get_project_detail(%s)", (23,)
        )

        assert result == record
```

*(Needs `from types import SimpleNamespace` and `from unittest.mock import
AsyncMock` — both already imported at the top of `test_deps.py` for
`TestCallProc`, no new imports required.)*
