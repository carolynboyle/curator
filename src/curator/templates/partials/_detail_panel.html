{# _detail_panel.html Genuinely empty shell for the detail panel container — no entity, no record data. This is the ONE render of this file that happens via crew.html at initial page load, and it's invisible: the panel sits hidden behind the hero image until someone clicks ⋯ or + Add. From that point on, panel.py is the sole renderer of real content — /panel/{entity}/{id} (or .../new) returns _detail_panel_content.html fully populated, and detail-panel.js's fetchAndSwapPanel() replaces this div's entire innerHTML with it. Previously received entity='projects'/record_id=0/record={}/ project_types/project_statuses from crew.html — all vestigial. project_types/project_statuses aren't referenced anywhere in _detail_panel_content.html (fieldkit replaced that raw-lookup approach), and entity/record_id were rendering a fake "projects" panel nobody ever saw before panel.py overwrote it on first open. Removed outright rather than defended against with fallback values — a second code path capable of rendering this content, even one that's invisible, is exactly the duplication fieldkit's design was meant to eliminate. #}
